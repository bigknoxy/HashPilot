# HashPilot — Full Audit & Prioritized Backlog

**Date:** 2026-08-07
**Commit:** `d89d40e` (main, clean)
**Method:** 4-expert panel (correctness/reliability, CLI-UX/agent-ergonomics, competitive+research landscape, security/ops/distribution) reading real source, plus live reproduction of every P0 finding by the coordinator.
**Baseline:** `bun install && bun test` → **344 pass / 0 fail**. The suite is green *and* the P0 defects below are live. They are tested-in behavior, not regressions.

---

## Executive summary

Three things matter more than everything else in this document.

**1. The core safety guarantee is inverted.** Hash anchoring exists to refuse an edit when the file moved. Instead, an unrecognized hash triggers "auto-recovery" that replaces the **entire file**, reports `success: true`, and exits `0`. Verified live. Combined with the absence of any write boundary (an agent-supplied `../outside.txt` escaped the project root and was overwritten) and the absence of atomic writes or backups, HashPilot can silently destroy arbitrary files with no recovery path. This is a data-loss product until B1–B4 ship.

**2. Every command exits 0, including failures.** `ast rename-symbol` on a nonexistent symbol returns `success: false` and exits `0`. `diff apply` without `--patch` throws a raw stack trace and *still* exits `0`. Every CI pipeline and every agent that checks `$?` currently treats failure as success. This one-line-per-command fix is the highest value-to-effort item in the backlog.

**3. The headline differentiator is already commoditized, and it targets a 5% problem.** Hash-anchored editing ships today in oh-my-pi, hashline, oh-my-opencode, pi-hash-anchored-edit and pi-hashline-edit — several with LSP and subagents on top. Meanwhile SWE-bench failure analysis puts *anchor mismatch at ~5%* of agent edit failures and *"incomplete fix / missed call sites" at 62%* — the bucket that needs reference resolution HashPilot does not have. The defensible ground is **telemetry-driven route health, edit-time provenance, and declarative route policy**, none of which any competitor surfaces. Reposition around those.

Against a 2026 table-stakes checklist HashPilot scores roughly **4 yes / 3 partial / 10 no**. The biggest structural gaps: no MCP server, no LSP, 6 languages (vs Serena's 30+), no published benchmark numbers, no session-level undo.

## Scoring model

`Score = (Impact × 5) + (Evidence × 2) − (Effort × 2)`

- **Impact** 1–10 — blast radius if left unfixed (data loss and silent-wrong-answer rank highest).
- **Evidence** 1–10 — 10 = reproduced live by the coordinator; 8 = cited file:line read by an expert; 5 = reported, unverified.
- **Effort** 1–10 — engineering days-ish, 1 = under an hour, 10 = multi-week.

Tiers: **P0** ≥ 55 · **P1** 40–54 · **P2** 25–39 · **P3** < 25.

## Recommended sequencing

**Sprint 1 — stop the bleeding (B1, B2, B3, B5, B7, B11, B13, B20).** Mostly small, all high-scoring. Ends with: failures exit non-zero, anchors refuse instead of overwrite, writes can't escape the repo, and the advertised-but-broken `remove-parameter` is gone or fixed.

**Sprint 2 — foundations (B4, B6, B8, B15, B16, B18, B19, B31, B32).** Atomic writes + undo, wired telemetry consent, the parse-validity gate, and one JSON envelope. After this the tool is trustworthy enough to recommend.

**Sprint 3 — parity (B21 MCP, B22 benchmarks, B33 CI matrix, B34 distribution, B24 interactive, B27/B28 conformance tests).** After this it is competitive.

**Then — B23 LSP.** The largest single lever on real-world success rate, and the largest effort. Sequence it once the foundations can't corrupt anything.

## Positioning note

Drop "hash anchoring is our differentiator" — it is table stakes in this cluster now and it addresses ~5% of observed edit failures. Lead instead with the three things nobody else does: **route policy that auto-tunes from observed per-language failure rates** (a self-calibrating edit router is a genuinely unclaimed idea, and the telemetry to drive it already exists), **edit-time provenance** emitted in a `git-ai`-compatible form so it rides the emerging standard rather than competing with it (the EU AI Act's machine-readable disclosure requirement lands Aug 2026), and **declarative per-model edit-format policy** — which the Diff-XYZ paper supports, since the best format is model- and size-dependent.
